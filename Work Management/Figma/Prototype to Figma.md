# 프로토타입을 피그마로 작성 프롬프트

## 프로토타입 피그마 작성 요청

지금까지 만든 [프로토타입 파일명] 프로토타입을 개발팀 전달 수준의 Figma 설계로 작성해줘.
"액션에 따른 화면 플로우 보드" 형태로, 케이스와 상태별 화면 variant까지 포함해서.

소스는 아래 순서로 참고해줘
- 동작 프로토타입(정답 기준): [프로토타입 파일명] — 로직·데이터·상태전이·필수값 검증의 최종 기준
- 요구사항: [PRD 명] (FR-/RA- 코드, 상태 흐름, 역할분리, 데이터모델)
- 디자인 시스템: Modulor CORE (fileKey OHu3YQ55gYCdOlTH0y9H4Q, 읽기전용) — 게시 라이브러리 실컴포넌트만 사용
- 산출 파일: [피그마 파일 경로, fileKey] — 여기 새 페이지에 작성
- 플로우 보드 참고 포맷: 설계_관리자 앱 (fileKey XO9Oi85tEkbJ04kz40D1bx, node 3802-72984) — 이 "Flow 1~N" 레이아웃/연결선/주석 스타일을 그대로 따를 것

제품/테마는 아래와 같아
- 제품 HomeDot, Theme=🏠 HomeDot + Modulor_Default=Contrast 고정. 색·간격·라운드는 전부 토큰 바인딩(hex/px 하드코딩 금지).
- 웹 프레임 1440px, 모바일(관리자 앱) 390px. 웹은 Web/* 스타일·Spacing_Web, 모바일은 _Mobile 컴포넌트·Spacing_Mobile.
- 도형으로 컴포넌트 흉내 금지. 없는 컴포넌트는 가장 가까운 CORE 컴포넌트로 대체하고 무엇을 대체했는지 프레임 노트에 명시.

각 "플로우"를 예시처럼 한 행(row)으로 구성:
- 행 머리에 [플로우명 · 트리거(액션) · 사용자 역할] 라벨 카드.
- 오른쪽으로 화면을 "액션 → 다음 화면" 순서대로 나열하고, 화면 사이를 화살표(연결선)로 잇고 연결선 위에 [사용자 액션/조건] 라벨을 단다.
- 분기(케이스)와 상태(state)가 갈리면 화면을 아래로 분기시켜 variant를 나란히 배치.

작성할 플로우(프로토타입 기준, 최소 기준):
- 웹
1) 위탁사: 표준 체크리스트/유해위험요인 관리(상속) · 총괄 대시보드 모니터링·독촉 · 안전보건교육 이수현황
2) 관리소장: 계획 확인 → 상세 작성(점검자 배정) → 결재(상신대기·결재대기·완료)
3) 안전점검: 계획등록 모달 → 상세 → ②결과등록 → ③개선조치 → 보고서
4) 위험성평가: 등록 → 항목구성 → ②결과등록(3×3 매트릭스) → ③개선조치 → ④결재
5) 체크리스트 관리(3계층: 공통/위탁사추가/단지추가) 목록·상세·등록 모달
관리자 앱(모바일)
6) 점검자: 안전 일정 → 안전점검 결과 등록
7) 참석자: 위험성평가 수행(가능성 선택·중대성 고정, 조정 시 사유 필수)
8) 담당자: 개선조치 수행(조치완료/현재상태 유지·사유·전후사진)

케이스(분기)로 반드시 화면을 나눌 것
- 역할: 단지 vs 위탁사 / 점검자·관리소장·담당자·참석자
- 결재 사용 on/off(단지 설정) → 상신·결재 스킵 분기
- 종합판정: 전항목 적합 vs 부적합/추가발견 존재
- 체크 항목: 측정형(실측값 입력) vs 비측정
- 3계층 상속: 공통(🔒 읽기전용) vs 위탁사추가 vs 단지추가
- 조치 결과: 조치완료 vs 현재상태 유지(위험 수용)

[상태(state)별 화면 variant를 각 목록/폼마다 포함]
- 상태 흐름 배지: 안전점검 점검준비→계획등록→조치중→상신대기→결재대기→완료 / 위험성평가 평가준비→…→완료
- 화면 상태: 기본 / 빈 상태 / 로딩 / 에러 / 권한없음(위탁사 읽기전용) / 완료
- 폼 검증 상태: 필수값 미입력 시 "필수 항목 확인" 팝업 + 입력칸 에러 강조 + 라벨 * 표시 (프로토타입과 동일 규칙)
- 단계 게이팅: 상세 저장 전/후, 결과 저장 전/후로 열리는 영역 차이

[개발 전달용 주석(핸드오프)]
각 화면에 노트로: 필드 목록·필수/선택·검증 메시지·상태 전이 조건·연동(통합업무계획/임직원 마스터)·사용 컴포넌트/토큰명. 상태 전이는 연결선 라벨로 표기.

[프레임 네이밍]
`[플로우번호]-[화면명] · [상태/케이스] · [Web/Mobile]` (예: `3-안전점검 결과등록 · 부적합 · Web`).

[작업 방식]
- 먼저 전체 플로우 인덱스(보드 구조)를 만들고, 플로우 1개(안전점검)를 파일럿으로 완성해 리뷰받은 뒤 나머지를 같은 규칙으로 확장.
- 완료 후 각 프레임 스크린샷으로 자체 검증(토큰·잘림·플레이스홀더·상태 배지·필수 표시)하고, 보드 링크와 커버리지 체크리스트(플로우×케이스×상태 매트릭스)를 공유.
